==========================================================================
      LEVEL 3: THE "BRAIN" (Logic, Ranges, MultiTraits & Stats)
==========================================================================

GOAL: Build entities that follow strict internal rules, carry multi-item
loadouts, roll numeric ranges, and have balanced, trait-modified stats.

In Level 2, we controlled rarity. In Level 3, we wire up the engine's
logic so traits unlock or block each other, items modify stats, and
every number stays mathematically sound.

--------------------------------------------------------------------------
[ 1. THE TAG SYSTEM (Logic Gates) ]
--------------------------------------------------------------------------

Tags are the hidden flags of the engine. They are case-insensitive and
act as keys to unlock or block later options:

  - StartingTags: Tags granted immediately (e.g., ["Martial", "Human"]).
  - GrantsTag:    New tag(s) added when an option is rolled.
  - Requires:     Hides an option unless ALL listed tags are active.
  - Excludes:     Blocks an option if ANY listed tag is active.

MULTI-TAG SUPPORT:
You can list multiple tags separated by commas in GrantsTag, Requires,
or Excludes:

  "GrantsTag": "Heavy_Armor, Veteran"
  "Requires":  "Martial, Veteran"
  "Excludes":  "Heavy_Armor, Pacifist"

--------------------------------------------------------------------------
[ 2. GENDER-LOCKED IDENTITY ]
--------------------------------------------------------------------------

When UseGender is true, the engine rolls Gender BEFORE Names and adds
the rolled gender (e.g., "Male", "Female", "Non-Binary") as a Tag.

  { "Value": "Arthur",    "Weight": 10, "Requires": "Male" }
  { "Value": "Guinevere", "Weight": 10, "Requires": "Female" }
  { "Value": "Rowan",     "Weight": 3 }

Weight Tip: If you mix gendered names with gender-neutral names, give
gendered names a higher Weight (e.g., 10 vs. 3) so neutral names do not
crowd out Male/Female rolls while still giving Non-Binary a clean pool.

--------------------------------------------------------------------------
[ 3. MULTITRAITS (Inventories, Loadouts & Quirks) ]
--------------------------------------------------------------------------

When UseMultiTraits is true, MultiTraits let you roll multiple items
from a single pool (like field gear, spells, or physical tells):

  - Chance:          0.0 to 1.0 chance the pool rolls at all.
  - MinPicks / MaxPicks: Random number of items drawn from Options.
  - AllowDuplicates: false prevents picking the same item twice.
  - Requires / Excludes: Optional pool-level AND item-level tag gates.

--------------------------------------------------------------------------
[ 4. NUMERIC RANGES (Age, Height, Bounty, etc.) ]
--------------------------------------------------------------------------

When UseRanges is true, Ranges roll independent numbers with optional
step sizes, display units, and tag gates:

  "Bounty": {
    "Min": 500, "Max": 3000, "Step": 250,
    "Unit": " Cr", "Requires": "Veteran"
  }

Note: Negative Min values (like "-180" for planet temperature) are fully
supported. Include a leading space in Unit if you want spacing (" yrs").

--------------------------------------------------------------------------
[ 5. POINT POOL MATH & STATMODS ]
--------------------------------------------------------------------------

PointPools distribute a budget of points across custom attributes. To
avoid everyone capping out at the maximum, balance your budget:

  Formula: (Target Average) x (Attribute Count) = TotalPoints

  - BAD MATH:  60 points into 3 stats (Max 18) -> 3 x 18 = 54.
               Every stat hits 18 and the validator flags a Math Error.
  - GOOD MATH: 36 points into 3 stats (Min 6, Max 16) -> Average 12.
               Plenty of room for varied, distinct characters.

STATMODS (Trait Bonuses & Penalties):
Any option in Names, MandatoryTraits, OptionalTraits, or MultiTraits can
include a "StatMods" object to adjust PointPool stats OR Ranges after
they roll. Deltas display automatically on the sheet (e.g., "14 (+2)"):

  "StatMods": { "Strength": 2, "Agility": -1, "Bounty": 500 }

--------------------------------------------------------------------------
[ 6. THE GENERATION CHAIN (Strict Order) ]
--------------------------------------------------------------------------

The engine always executes in this exact sequence:

  1. StartingTags    ->  2. Gender & Pronouns  ->  3. Names
  4. MandatoryTraits ->  5. OptionalTraits     ->  6. MultiTraits
  7. Ranges          ->  8. PointPools         ->  9. StatMods
  10. Narrative (BioTemplates)

An option can only Require a tag granted in an EARLIER step (or an
earlier trait inside the same section). If you reference a tag out of
order or misspell it, the Pre-Flight Validator will warn you on load.
